\section{Introduction}

Given a list of $n$ positive numbers $p_1, \ldots, p_n$ such that $\sum_i p_i = 1$, consider the basic task of picking an index $i$ at random with probability $p_i$. Two constant-time operations are assumed to be available:
\begin{compactenumI}
    \smallskip%
    \item \AlgorithmI{rand}($n$): Given an integer $n$, returns a real
    number uniformly at random from$[0,n)$
  
    \smallskip%
    \item The floor function $\floor{ \cdot }$.
\end{compactenumI}
\smallskip%
The \emphi{alias method} is described below. After linear-time
preprocessing, it enables sampling from this discrete distribution in
worst-case constant time.

\section{The alias method}

\paragraph*{Idea.}
The algorithm redistributes the probabilities into $n$ buckets, where each bucket is selected with probability $1/n$. Each bucket stores either one value or two original values, and a threshold specifies how to choose between them.

An elegant way to think about this is to view each probability $p_i$ as
an interval of length (you guessed it) $p_i$, with $i$ being its
\emphi{label}.  These intervals tile/cover the interval $[0,1]$. Think
about marking each interval by its label (i.e., the value $i$ that it
represents). Then, choosing a random value $i$ according to this
distribution is easy---we randomly pick a value $x \in [0,1]$, and pick the
interval in this partition that contains $x$. Naively, using binary
search over prefix sums, this takes $O( \log n)$ time per query---terribly
slow, unacceptable even.

The key insight to doing better is to break each input interval into
several intervals (at most $2n$ intervals overall), and rearrange them,
such that the tiling they generate has a special structure---the numbers
$i/n$ are always endpoints of intervals in this tiling. Furthermore, each
fragment has the label of the original interval it came from. Thus, the
total length of all the fragments labeled by $i$ is still going to be
exactly $p_i$. Thus, picking a label using the same algorithm would yield
a random sample with the desired distribution.

\paragraph*{The algorithm.}

The algorithm partitions the input intervals into three queues:
\smallskip
\begin{compactenumI}
    \item Too small: $S = \Set{(i,p_i)}{ p_i < 1/n}$.

    \smallskip%
    \item Too perfect: $M = \Set{(i,p_i)}{ p_i = 1/n}$.

    \smallskip%
    \item Too large: $L = \Set{(i,p_i)}{ p_i > 1/n}$.
\end{compactenumI}
\medskip%

As long as the queues are not empty, the algorithm continues running.
There are several cases.  \subparagraph*{There is an interval of length
   $1/n$:} If there is any interval in $M$, the algorithm uses it in the
tiling (i.e., it is tiling the interval $[0,1]$ from left to right) and
moves on to the right.

\subparagraph*{No interval of length $1/n$:} If $M$ is empty, and the
algorithm already generated $i$ tiles, then the number of intervals in
the two queues is exactly $n-i$. The remaining length to tile is
$T = (n-i)/n$. Thus, the average length of the remaining intervals is
exactly $T / (n-i) = 1/n$. By the pigeonhole principle, since none of
remaining intervals can have length $1/n$ (as $M = \emptyset$), it must be that
both the small queue and the large queue are not empty. Indeed, if all
remaining intervals were $< 1/n$, the average would be $< 1/n$; if all
were $> 1/n$, the average would be $> 1/n$. Thus, both $S \neq \emptyset$ and
$L \neq \emptyset$.

There is a bad choice here\footnote{%
   The temptation is to take a large interval, break it into a tile of
   size $1/n$, and the remainder, tile the part of size $1/n$ and
   continue. The problem is that the size of the queues remains the same,
   so that is a bad idea.}, but the right choice is to pop a small
element $s$ from $S$. To complete it, we also pop $\ell$ a large element
from $L$. We have $s < 1/n < \ell$. The new tile is going to be made of two
parts $s$ and $\delta =1/n-s$, where the latter part $\delta$ is taken from
$\ell$. That is, we have our tile made of two fragments of original
intervals $s$ and $\delta$ (labeled with the label of $s$ and the label
$\ell$, respectively). The interval $\ell$ however paid for this dearly---its
length now has shrunk to $\ell' = \ell - \delta = \ell - (1/n - s)$. The algorithm now
outputs the new tile (made of two fragments of original intervals, as
promised), and the residual interval $\ell'$ is now pushed back into the
appropriate queue (into $L$ if $\ell' > 1/n$, into $M$ if $\ell' = 1/n$, and
into $S$ if $\ell' < 1/n$).

\paragraph*{Analysis.}    
In the latter case, the algorithm popped two intervals, pushed back one
subinterval, and output one tile. Namely, the algorithm preserved the
invariant that at each step one tile of length $1/n$ was output, and the
total size of the queues shrunk by one in each iteration (in the first
case where an item is taken from $M$, one interval is popped and none
pushed back, also reducing the total queue size by one).

The correctness of the algorithm is now clear, as inductively it keeps
the above invariant till the end. The algorithm computes $n$ tiles
(i.e. \emphw{buckets}), numbered say $0, \ldots, n-1$, and each tile contains
one or two fragments.

\subparagraph*{Running time: Construction.} Clearly, each iteration takes
$O(1)$ time, and there are exactly $n$ iterations.

\paragraph*{The query algorithm: Picking a value.}
The algorithm picks a value $X \in [0,n)$ by calling
$\AlgorithmI{rand}(n)$. It then computes the bucket index
$Y = \floor{X} \in \{0, \ldots, n-1\}$. If this bucket has only a single
interval (with label $i$) associated with it, it returns the label
$i$. Otherwise, the bucket contains a primary fragment of length $s$ (say
label $\alpha$), designated in advance, and an alias fragment of length
$1/n - s$ (say labeled $\beta$). The algorithm computes the fractional offset
$\Delta = X - Y \in [0,1)$---this quantity being the distance of the random number
$X$ from the beginning of the bucket/tile that contains it (note that
$\Delta < 1/n$).  If $\Delta \leq s$, it returns the label of the primary
$\alpha$ and otherwise it returns the label of the alias $\beta$.

(All we did here was the good old search over the suffix sums,
implemented in a faster way, because of the nice structure computed.)

\subparagraph*{Running time: Query.} A few operations are performed, each
one takes constant time, so the query time is $O(1)$ worst-case.

\bigskip
We thus got the following result.

\begin{theorem}
    Given a discrete distribution with $n$ values, the above algorithm
    constructs, in $O(n)$ time, a data-structure that can compute samples
    according to this discrete distribution in $O(1)$ worst-case time per
    query. The algorithm relies on having access to the floor function,
    and the ability to sample uniformly from $[0,n)$ in constant time.
\end{theorem}

\section{Bibliographical notes}

The linear-time algorithm described here is due to Vose
\cite{v-lagrn-91}, building upon the original alias method developed by
Walker \cite{w-nfm-74, w-emg-77}. The problem where the randomness source
is simply an unbiased coin flip is also interesting, where one can
achieve the entropy of the discrete distribution for the expected number
of coin flips needed.

If the source of randomness is a number picked uniformly at random from
some \emph{discrete} set $ \{1,\ldots, m \}$, then doing expected $O(1)$ time
is possible. Using the alias method for the top level (pick the bucket),
and then resolving the two values inside the bucket, reduces this case
nicely to choosing only two values.  Note that the expected query time is
$O(1)$, but the worst case query time is unbounded, as no finite sequence
of rational probabilities can lead to an irrational probability.

As a toy example, the reader can consider the problem of choosing between
two values with probabilities $1/3$ and $2/3$ respectively, using an
unbiased coin. Describing the algorithm as a search tree over the binary
strings leads easily to the conclusion that this tree has unbounded
depth.
