Here, we are interested in the \emphi{streaming model}---where the input
arrives one item at a time, and usually we can store only a limited amount
of information---usually only a sliver of the original data.  Surprisingly,
we can still do various tasks efficiently, mostly by using randomness.

\section{The secretary problem}

Assume that we are seeing $n$ applications: $\alpha_1, \ldots, \alpha_n$, where they
arrive in random order. We would like to hire the best one, but we have
to make an immediate decision -- we see candidate $\alpha_i$, we either hire
them (and then we are stuck with them), or we let them go and see the
next candidate. We win the game if we hire the best candidate out of the
$n$ candidates.


The question is what is the natural strategy to win the game?  Let
$P(r)$ be the probability that we win, when the strategy is to see the
first $r-1$ candidates, and then hire the first candidate we see in
$\alpha_r, \ldots, \alpha_n$ that is better than all the candidates
seen in $\alpha_1, \ldots, \alpha_{r-1}$.
Let $\Event_i$ be the event that the $i$\th candidate is the best.
We have that
\begin{align*}
    P(r)
    &=%
    \sum_{i=1}^{n} \Prob{\bigl. \text{applicant $i$  is selected}
       \cap
       \Event_i}
    \\&%
    =%
    \sum_{i=1}^{n}\ProbCond{\text{applicant  $i$  is
          selected}}{\Event_i}
    \cdot \Prob{\Event_i}
    \\&%
    =%
    \frac{1}{n}
    \left[\sum
      _{i=1}^{r-1}0+\sum
      _{i=r}^{n}\ProbCond{
         \begin{array}{l}
           \text{best of first }
           i-1
           \text{applicants}\\
           \text{is in the first }
           r-1
           \text{applicants}
         \end{array}
      }{\Event_i}
      \right]
      \\
      &=
      \frac {1}{n}
      \left[
        \sum _{i=r}^{n}{\frac
           {r-1}{i-1}}
      \right]\
      \\
      &=
      {\frac {r-1}{n}}\sum _{i=r}^{n}{\frac{1}{i-1}}.
\end{align*}
Observe that 
\begin{equation*}
    \sum _{i=r}^{n}\frac{1}{i-1}
    \leq%
    \int_{x=r-2}^{n-1} \frac{1}{x} \diffX{x}
    =%
    \ln (n-1) - \ln (r-2)
    \approx
    \ln \frac{n}{r}.
\end{equation*}
For $r= n/e$, we have that
$P(r) \approx \frac{r}{n} \ln \frac{n}{r} = \frac{1}{e} \ln e =1/e$.

\section{Reservoir sampling: Fishing a sample from a stream}
\seclab{reservoir:sampling}

Imagine that you are given a stream of elements $s_1, s_2, \ldots$,
and you need to sample $k$ numbers from this stream (say, without
repetition) -- assume that you do not know the length of the stream in
advance, and furthermore, you have only $O(k)$ space available for
you. How to do that efficiently?


There are two natural schemes:
\medskip
\begin{compactenumA}
    \item Whenever an element arrives, generate a random number for it
    in the range $[0,1]$. Maintain a heap with the $k$ elements with
    the lowest priority. Implemented naively this requires
    $O( \log k)$ comparisons after each insertion, but it is not
    difficult to improve this to $O(1)$ comparisons in the amortized
    sense per insertion. Clearly, the resulting set is the desired
    random sample.
    
    \medskip
    \item \itemlab{rand:s:sample} %
    Let $S_t$ be the random sample maintained in the $t$\th iteration.
    When the $i$\th element arrives, the algorithm flips a coin that is
    heads with probability $\min(1,k/i)$. If the coin is heads then it
    inserts $s_i$ to $S_{i-1}$ to get $S_i$. If $S_{i-1}$ already has
    $k$ elements, then first randomly delete one of the elements.
    If the coin is tails leave the sample unchanged.
\end{compactenumA}


\begin{theorem}
    \thmlab{stream:sample}%
    %
    Given a stream of elements, one can uniformly sample $k$ elements
    (without repetition), from the stream using $O(k)$ space, where
    $O(1)$ time is spent for handling each incoming element.
\end{theorem}
\begin{proof}
    We implement the scheme  \itemref{rand:s:sample} above. We only
    need to argue that this is a uniform random sample. The claim
    trivially holds for $i=k$. So assume the claim holds for $i <t$,
    and we need to prove that the set after getting $t$\th element is
    still a uniform random sample.

    So, consider a specific set $K \subseteq \brc{s_1,\ldots, s_t}$ of
    $k$ elements.  The probability of $K$ to be a random sample of
    size $k$ from a set of $t$ elements is $1/\binom{t}{k}$. We need
    to argue that this probability remains the same for this scheme.
    
    So, if $s_t \notin K$, then we have
    \begin{align*}
        \Prob{K = S_t}%
        &\EQ%
        \Prob{K = S_{t-1} \text{ and } s_t \text{ was not inserted}}%
        =%
        \frac{1}{\binom{t-1}{k}} \pth{ 1-\frac{k}{t}}
        \\&%
        \EQ%
        \frac{k! (t-1-k)! ( t-k)}{(t-1)! t}
        =%
        \frac{1}{\binom{t}{k}}.        
    \end{align*}
    
    If $s_t \in K$, then
    \begin{align*}
        \Prob{\bigl. K = S_t}%
        &\EQ%
        \Prob{
           \begin{array}{c}
             K \setminus \brc{s_t} \subseteq S_{t-1},\\
             s_t \text{ was inserted}\\
             \text{and } S_{t-1}\setminus K \text{ thrown out of } S_{t-1}
           \end{array}
        }%
        \\&
        \EQ%
        \frac{t-1-(k-1)}{\binom{t-1}{k}}%
        \frac{\bcancel{k}}{t}
        \frac{1}{\bcancel{k}}
        \EQ%
        \frac{(t-k) k! (t-1-k)! }{(t-1)! t}        
        \\&
        \EQ%
        \frac{1}{\binom{t}{k}},
    \end{align*}
    as desired. Indeed, there are $t-1-(k-1)$ subsets of size $k$ of
    $\brc{s_1, \ldots, s_{t-1}}$ that contain
    $ K \setminus \brc{s_t}$ -- since we fix $k-1$ of the $t-1$
    elements.
\end{proof}

\section{Sampling and median selection revisited}

Let $B[1,\ldots, n]$ be a set of $n$ numbers. We would like to
estimate the median, without computing it outright. A natural idea,
would be to pick $k$ elements $e_1, \ldots, e_k$ randomly from $B$,
and return their median as the guess for the median of $B$.

\providecommand{\rankY}[2]{{R^{}_{#1}}\pth{#2}}%

In the following, let $\rankY{B}{t}$ be the $t$\th smallest number in
the array $B$.

\begin{observation}
    For any $\eps \in (0,1)$, we have that
    \begin{math}
        \frac{1}{1-\eps} \geq 1+\eps.
    \end{math}
\end{observation}

The following is a strengthening of the original analysis we did for
median selection. Here, we use Chernoff inequality instead of Chebychev,
thus getting stronger bounds.

\begin{lemma}
    Let $\eps, \BadProb \in (0,1/2)$ be fixed parameters, and let $B$ be a set
    of $n$ numbers. Let $Z$ be the median of the random sample (with
    replacement) of $B$ of size $k$.  We have that
    \begin{equation*}
        \Prob{\Bigl. \rankY{B}{ \smash{\frac{1-\eps}{2}{n}}
           }
           \leq%
           Z%
           \leq%
           \rankY{B}{ \smash{\frac{1+\eps}{2} n}}%
        }
        \geq%
        1-\BadProb,
        \qquad\text{where}\qquad%
        k\geq \ceil{\frac{12}{ \eps^2} \ln \frac{2}{\BadProb}}.
    \end{equation*}
    Namely, with probability at least $1-\BadProb$, the returned value
    $Z$ is $(\eps/2)n$ positions away from the true median.
\end{lemma}

\begin{proof}
    Let $L = \rankY{B}{(1-\eps)n/2}$, and let $e_i$ be the $i$\th
    sample number, for $i=1,\ldots, k$.  Let $X_i=1$ if and only if
    $e_i \leq L$. We have that
    \begin{equation*}
        \Prob{X_i =1 } = \frac{ (1-\eps)n/2}{n} = \frac{1-\eps}{2}.        
    \end{equation*}
    As such, setting $Y = \sum_{i=1}^k X_i$, we have
    \begin{equation*}
        \mu = \Ex{Y} = \frac{1-\eps}{2}  k%
        \geq%
        \frac{k}{4} \geq
        \frac{3}{\eps^2} \ln \frac{2}{\BadProb} .
    \end{equation*}

    The lower-tail failure event is contained in the event $Y \geq
    k/2$. Since $\tfrac{1}{1-\eps} \geq 1+\eps$, we have that
    \begin{align*}
        \Prob{Y \geq k/2}%
        &\EQ %
        \Prob{Y \geq \frac{1/2}{(1-\eps)/2} \cdot \frac{1-\eps}{2} k}%        
        \leq%
        \Prob{Y \geq (1+\eps) \mu}%        
        \\&
        \LEQ %
        \exp\pth{ - \frac{\eps^2 \mu}{3}}
        \leq %
        \exp\pth{ - \frac{\eps^2}{3} \cdot         \frac{3}{\eps^2} \ln \frac{2}{\BadProb} 
        }
        \leq%
        \frac{\BadProb}{2}.
    \end{align*}
    by \lemrefY{Chernoff's inequality}{chernoff:small:delta:1}.

    This implies that
    $\Prob{\bigl. \rankY{B}{(1-\eps)n/2} > Z } \leq \delta/2$.  The
    claim now follows by realizing that by symmetry (i.e., reversing
    the order), we have that
    \begin{equation*}
        \Prob{ Z > \rankY{B}{(1+\eps)n/2} }
        \LEQ
        \BadProb /2,
    \end{equation*}
    and putting these two inequalities together.
\end{proof}

For exact median selection, we need two sample order statistics that
bracket the true median, and leave only a short interval of possible
ranks. The following lemma gives both guarantees. Then, the algorithm can
simply filter all the elements that fall within this interval. The double
bounds below ensure this interval is not too long.

\begin{lemma}
    \lemlab{stronger:median}%
    %
    Let $\eps, \BadProb \in (0,1/2)$, $B$ an array of $n$ elements, and let
    $S = \brc{e_1, \ldots, e_k}$ be a set of $k$ samples picked uniformly and
    randomly (with repetition) from $B$. Then, for some absolute constant
    $c$, and an integer $k$, such that
    $k\geq \ceil{\frac{c}{\eps^2} \ln \frac{1}{\BadProb}} $, we have that
    \begin{equation*}
        \Prob{%
           \rankY{S}{k_- }
           \leq
           \rankY{B}{n/2}
           \leq
           \rankY{S}{k^+} }
        \geq 1-\BadProb.
    \end{equation*}
    for $k_- = \floor{(1-\eps)k/2}$, and $k^+ = \floor{(1+\eps)k/2}$.  Ignoring
    floor functions for simplicity, the following stronger statement is correct:
    \begin{equation*}
        \Prob{%
           \rankY{B}{(1-2\eps)n/2}
           \leq %
           \rankY{S}{(1-\eps)k/2 }
           \leq
           \rankY{B}{n/2}
           \leq
           \rankY{S}{(1+\eps)k/2}
           \leq%
           \rankY{B}{(1+2\eps)n/2}
        }
      %\\&
      \geq 1-\BadProb        
    \end{equation*}
    (the constant $c$ would have to be slightly bigger).
\end{lemma}


\subsection{A median selection with few comparisons}

The above can be plugged into the two round randomized selection
algorithm we had seen before. Since we used Chernoff's inequality, we get
a somewhat stronger result. Interestingly, the algorithm needs to scan
the data only twice. We omit the easy and tedious details since they just
involve plugging in the improved sampling lemma in the previous
algorithm -- here the sample is going to be of size $O(n^{2/3})$.


\begin{lemma}
    Consider a stream $B$ of $n$ numbers, and assume we can make two
    passes over the data. Then, one can compute exactly the median of
    $B$ using:
    \begin{compactenumI}
        \item $O(n^{2/3})$ space.
        \item $1.5n + O(n^{2/3} \log n)$ comparisons.
    \end{compactenumI}
    The algorithm reports the median correctly, and it succeeds with
    high probability.
\end{lemma}

\begin{remark}
    Interestingly, one can do better if one is more careful. The basic
    idea is to do thinning -- given two sorted sequences of size $s$,
    consider merging the sets, and then picking all the even rank
    elements into a new sequence. Clearly, the element of rank $i$ in
    the output sequence, has rank $2i$ in the union of the two
    original sequences. A sequence that is the result of $i$ such
    rounds of thinning is of \emphOnly{level}\index{level} $i$. We maintain
    $O( \log n)$ such sequences as we read the stream. At any time, we
    have two buffers of size $s$, that we fill up from the
    stream. Whenever the two buffers fill up completely, we perform
    the thinning operation on them, creating a sequence of level $1$.

    If during this process we have two sequences of the same level, we
    merge them and perform thinning on them. As such, we maintain
    $O( \log n)$ buffer sequences each of size $s$. Assume that our
    stream has size $n$, and $n$ is a power of $2$. Then in the end of
    process, we would have only a single sequence of level
    $h = \log_2(n/s)$. Every element rank can be estimated roughly within
    an additive factor of $h2^h$ (proving the exact bound here is quite
    tedious).

    Thus, setting $s=\sqrt{n}$, we get that after a single pass, using
    $O( \sqrt{n} \log n)$ space, we have a sorted sequence, where the
    rank of the elements is roughly $\sqrt{n}$ approximation to the true
    rank. We pick the two consecutive elements (or more carefully, the
    predecessor, and successor), and filter the stream again, keeping
    only the elements in between these two elements. It is to show that
    (roughly) $O( \sqrt{n} \log n)$ would be kept, and we can extract the
    median using (roughly) $O( \sqrt{n} \log^2 n)$ time.

    We thus got that one can compute the median in two passes using
    $O(\sqrt{n} \log n)$ space. It is not hard to extend this
    algorithm to $\alpha$-passes, where the space required becomes
    $O(n^{1/\alpha} \log^{O(1)} n)$.

    This elegant algorithm goes back to 1980, and it is by Munro and
    Paterson \cite{mp-ssls-80}.
    The exact rank bounds for this thinning procedure, including matching
    examples, are proved in \secref{thinning:appendix}.
\end{remark}

\section{Big data and the streaming model}

Here, we are interested in doing some computational tasks when the
amount of data we have to handle is quite large (think terabytes or
larger).  The main challenge in many of these cases is that even
reading the data once is expensive. Running times of $O(n \log n)$
might not be acceptable. Furthermore, in many cases, we can \emph{not}
load all the data into memory.

In the \emphOnly{streaming}\index{streaming} model, one reads the data as it comes in, but
one can not afford to keep all the data. A natural example would be an
internet router, which has gazillion of packets going through it every
minute. We might still be interested in natural questions about these
packets, but we want to do this without storing all the packets.

\section{Heavy hitters}

\paragraph*{The problem.}
Imagine a stream $s_1,\ldots$, where elements might repeat, and we
would like to maintain a list of elements that appear at least
$\eps n$ times, where $\eps \in (0,1)$ is some parameter. The purpose
here is to do this using as little space as possible.

\subsection{A randomized algorithm}

An easy randomized algorithm, with target failure probability $\BadProb$,
would maintain a random sample of size
$m = \ceil{(1/\eps) \ln( 1/\eps\BadProb)}$, using \secrefY{reservoir
   sampling}{reservoir:sampling}. The probability the sample fails to
contain a heavy hitter after $t$ insertions is
\begin{align*}
    (1-\eps)^m
    &\LEQ
    \exp(-\eps m )%
    \leq%
    \exp\pth{-\eps \ceil{\frac{1}{\eps} \ln \frac{1}{\eps \BadProb}} }%
    \leq 
    \exp\pth{- \ln \frac{1}{\eps \BadProb}}%
    \\&
    \EQ 
    {\eps \BadProb}.
\end{align*}
Applying the union bound to all $\floor{1/\eps}$ heavy hitters, we get an
overall failure probability $\leq \BadProb$.



\subsection{A deterministic algorithm}
Disclaimer: The following is a deterministic algorithm, but it is too
elegant to hold this against it, and we will present it anyway.


\paragraph*{The algorithm.}
To this end, let
\begin{equation*}
    k = \ceil{1/\eps}. 
\end{equation*}
At each point in time, we maintain a set $S$ of $k$ elements, with a
counter for each element. Let $S_t$ be the version of $S$ after $t$ were
inserted. When $s_{t+1}$ arrives, we do one of the following:
\begin{compactenumA}
    \smallskip%
    \item $s_{t+1}$ is in the set $S_t$. Then, we increase its counter.

    \smallskip%
    \item If $\cardin{S_t} < k$, then we insert $s_{t+1}$ to the set, and
    set its counter to $1$.

    \smallskip%
    \item Otherwise, $|S_t|=k$ and $s_{t+1} \notin S_t$. We then decrease
    all the $k$ counters of elements in $S_t$ by $1$. If a counter of an
    element in $S_{t+1}$ is zero, then we delete it from the set.
\end{compactenumA}
    


\paragraph*{Correctness.}

\begin{lemma}
    The above algorithm, after the insertion of $t$ elements, the set
    $S_{t}$ would contain all the elements in the stream that
    appears at least $\eps t$ times. 
\end{lemma}
\begin{proof}
    Conceptually, imagine that the algorithm keeps counters for all
    the distinct elements seen in the stream. Whenever a decrease of
    the counters happens -- the algorithm decreases not $k$ counters --
    but $k+1$ counters -- the additional counter being a counter of
    the new element, which has value one, and goes down to zero.
    Clearly, the number of distinct remaining elements at any point in
    time is at most $k$ -- that is, the number of counters that have a
    non-zero value.  Consider an element $e$ that appears
    $u \geq \eps t$ times in the stream. The counter for $e$ is going
    to be increased $u$ times, and decreased at most $\alpha$ times,
    where
    \begin{math}
        \alpha (k+1) \leq t.
    \end{math}
    We have that the counter for $u$ in the end of the stream must
    have value at least
    \begin{align*}
        u - \frac{t}{k+1}%
        &\GEQ%
        \eps t - \frac{t}{k+1}
        = 
        \eps t - \frac{t}{\ceil{1/\eps}+1}
        \\&
        \GEQ%
        t \frac{\ceil{1/\eps}\eps +\eps - 1}{\ceil{1/\eps}+1}
        \geq%
        t \frac{\eps}{\ceil{1/\eps}+1} > 0.
    \end{align*}
    This implies that the counter of $u$ is strictly larger than $0$,
    which implies that $u$ appears in $S_{t}$.
\end{proof}
