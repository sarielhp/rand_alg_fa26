\section{Introduction}



We are interested here in dictionary data structure. The settings for
such a data-structure:
\begin{compactenumA}
    \item $\cU$: universe of keys with total order: numbers, strings,
    etc.
    \item Data structure to store a subset $S \subseteq \cU$
    \item {\bfseries Operations:}
    \begin{compactenumA}
        \item \AlgorithmI{search}/\Algorithm{lookup}: given
        $x \in \cU$ is $x \in S$?
        
        \item \AlgorithmI{insert}: given $x \not \in S$ add $x$ to
        $S$.
        \item \AlgorithmI{delete}: given $x \in S$ delete $x$ from $S$
    \end{compactenumA}
    \medskip%
    \item \emphi{Static} structure: $S$ given in advance or changes
    very infrequently, main operations are lookups.
    \item \emphi{Dynamic} structure: $S$ changes rapidly so inserts
    and deletes as important as lookups.
\end{compactenumA}

\bigskip%

Common constructions for such data-structures, include using a static
sorted array, where the lookup is a binary search. Alternatively, one
might use a \emph{balanced} search tree (i.e., red-black tree). The
time to perform an operation like lookup, insert, delete take
$O(\log |S|)$ time (comparisons).

Naturally, the above are potently an ``overkill'', in the sense that
sorting is unnecessary. In particular, the universe $\cU$ may not be
(naturally) totally ordered.  The keys correspond to large objects
(images, graphs etc) for which comparisons are expensive.  Finally, we
would like to improve ``average'' performance of lookups to $O(1)$
time, even at cost of extra space or errors with small probability:
many applications for fast lookups in networking, security, etc.


\paragraph*{Hashing and Hash Tables.}%

The hash-table data structure has an associated (hash) table/array $T$
of size $m$ (the table \emphi{size}).  A hash function
$h: \cU \rightarrow \{0,\ldots,m-1\}$. An item $x \in \cU$ hashes to
slot $h(x)$ in $T$.


Given a set $S \subseteq \cU$, in a perfect ideal situation, each
element $x \in S$ hashes to a distinct slot in $T$, and we store $x$
in the slot $h(x)$. The \Algorithm{Lookup} for an item $y \in \cU$, is
to check if $T[h(y)] = y$. This takes constant time.

Unfortunately, \emph{collisions} are unavoidable, and several
different techniques to handle them.
Formally, two items $x \neq y$  \emphi{collide} if  $h(x) = h(y)$.

A standard technique to handle collisions is to use \emphi{chaining}
(aka \emph{open hashing}). Here, we handle collisions as follows:
\smallskip%
\begin{compactenumA}
    \item For each slot $i$ store all items hashed to slot $i$ in a
    linked list. $T[i]$ points to the linked list.
    
    \smallskip%
    \item \Algorithm{Lookup}: to find if $y \in \cU$ is in $T$, check
    the linked list at $T[h(y)]$. Time proportion to size of linked
    list.
\end{compactenumA}

    \centerline{\IncludeGraphics[width=3in]%
       {\File{figs/chaining_hash_table}}}
    \caption{Open hashing.}
\end{figure}

\smallskip%

Other techniques for handling collisions include associating a list of
locations where an element can be (in certain order), and check these
locations in this order. Another useful technique is \emphi{cuckoo
   hashing} which we will discuss later on: Every value has two
possible locations. When inserting, insert in one of the locations,
otherwise, kick out the stored value to its other location. Repeat
till stable. if no stability then rebuild table.
    
The relevant questions when designing a hashing scheme, include:
\begin{enumerate*}[label=(\Roman*)]
    \item Does hashing give $O(1)$ time per operation for
    dictionaries?
    \item Complexity of evaluating $h$ on a given element?

    \item Relative sizes of the universe $\cU$ and the set to be
    stored $S$.  \item Size of table relative to size of $S$.  \item
    Worst-case vs average-case vs randomized (expected) time?  \item
    How do we choose $h$?
\end{enumerate*}

The \emphi{load factor} of the array $T$ is the ratio $n/t$ where
$n = |S|$ is the number of elements being stored and $m = \cardin{T}$
is the size of the array being used.  Typically $n/t$ is a small
constant smaller than $1$.

In the following, we assume that $\cU$ (the universe the keys are
taken from) is large -- specifically, $N = \cardin{\cU} \gg m^2$,
where $m$ is the size of the table.  Consider a hash function
$h : \cU \rightarrow \{0,\ldots, m-1\}$.  If hash $N$ items to the $m$
slots, then by the pigeon hole principle, there is some
$i \in \{0,\ldots,m-1\}$ such that $N/m \geq m$ elements of $\cU$ get
hashed to $i$.  In particular, this implies that there is set
$S \subseteq \cU$, where $|S| = m$ such that all of $S$ hashes to same
slot. Oops.

Namely, for every hash function there is a \emph{bad set} with many
collisions.

\begin{observation}
    Let $\cH$ be the set of all functions from
    $\cU = \brc{1,\ldots, U}$ to $\brc{1, \ldots, m}$. The number of
    functions in $\cH$ is $m^U$. As such, specifying a function in
    $\cH$ would require $\log_2 \cardin{\cH} = O(U \log m)$.
\end{observation}

As such, picking a truely random hash function requires many random
bits, and furthermore, it is not even clear how to evaluate it
efficiently (which is the whole point of hashing).



\paragraph*{Picking a hash function.}
Picking a good hash function in practice is a dark art involving many
non-trivial considerations and ideas. For parameters $N = |\cU|$,
$m = |T|$, and $n = |S|$, we require the following:
\begin{compactenumA}
    \item $\cH$ is a \emphi{family} of hash functions: each function
    $h \in \cH$ should be efficient to evaluate (that is, to compute
    $h(x)$).
    
    \item $h$ is chosen \emph{randomly} from $\cH$ (typically
    uniformly at random). Implicitly assumes that $\cH$ allows an
    efficient sampling.
    
    \item Require that for any {\em fixed} set $S \subseteq \cU$, of
    size $m$, the expected number of collisions for a function chosen
    from $\cH$ should be ``small''. Here the expectation is over the
    randomness in choice of $h$.
\end{compactenumA}

\section{Universal Hashing}

We would like the hash function to have the following property -- For
any element $x \in \cU$, and a random $h \in \cH$, then $h(x)$ should
have a uniform distribution.  That is $\text{Pr}[h(x) = i] = 1/m$, for
every $0 \le i < m$. A somewhat stronger property is that for any two
distinct elements $x,y \in \cU$, for a random $h \in \cH$, the
probability of a collision between $x$ and $y$ should be at most
$1/m$. $\Prob{h(x) = h(y)} = 1/m$.

\begin{definition}
    \deflab{2:universal}%
    %
    A family $\cH$ of hash functions is \emphi{$2$-universal} if for
    all distinct $x,y \in \cU$, we have $\Prob{h(x) = h(y)} \leq 1/m$.
\end{definition}

Applying a $2$-universal family hash function to a set of distinct
numbers, results in a $2$-wise independent sequence of numbers.

% \subsubsection{Analyzing $2$-universal hashing}

\begin{lemma}
    Let $S$ be a set of $n$ elements stored using open hashing in a
    hash table of size $m$, using open hashing, where the hash
    function is picked from a $2$-universal family. Then, the expected
    lookup time, for any element $x \in \cU$ is $O(n/m)$.
\end{lemma}

\begin{proof}
    The number of elements colliding with $x$ is
    $\ell(x) = \sum_{y \in S} D_y$, where $D_y=1$ $\iff$ $x$ and $y$
    collide under the hash function $h$. As such, we have
    \begin{equation*}
        \Ex{\ell(x)}%
        =%
        \sum_{y \in S}\Ex{D_y}%
        =%
        \sum_{y \in S}\Prob{h(x) = h(y)}
        = \sum_{y \in S} \frac{1}{m}%
        = |S|/m 
        = n/m.
    \end{equation*}
\end{proof}

\begin{remark}
    The above analysis holds even if we perform a sequence of $O(n)$
    insertions/deletions operations. Indeed, just repeat the analysis
    with the set of elements being all elements encountered during
    these operations.

    The worst-case bound is of course much worse -- it is not hard to
    show that in the worst case, the load of a single hash table entry
    might be $\Omega(\log n/\log \log n)$ (as we seen in the occupancy
    problem).
\end{remark}

\paragraph*{Rehashing, amortization, etc. }
The above assumed that the set $S$ is fixed.  If items are inserted
and deleted, then the hash table might become much worse.  In
particular, $|S|$ grows to more than $cm$, for some constant $c$, then
hash table performance start degrading.  Furthermore, if many
insertions and deletions happen then the initial random hash function
is no longer random enough, and the above analysis no longer holds.

A standard solution is to rebuild the hash table periodically.  We
choose a new table size based on current number of elements in table,
and a new random hash function, and rehash the elements. And then
discard the old table and hash function.  In particular, if $|S|$
grows to more than twice current table size, then rebuild new hash
table (choose a new random hash function) with double the current
number of elements. One can do a similar shrinking operation if the
set size falls below quarter the current hash table size.
    
If the working $|S|$ stays roughly the same but more than $c|S|$
operations on table for some chosen constant $c$ (say $10$), rebuild.

The \emphi{amortize} cost of rebuilding to previously performed
operations. Rebuilding ensures $O(1)$ expected analysis holds even
when $S$ changes. Hence $O(1)$ expected look up/insert/delete time
{\em dynamic} data dictionary data structure!

\subsubsection{A quick reminder on working modulo prime}

\begin{defn}
    For a number $p$, let $\ZZ_n = \brc{0, \ldots, n-1 \bigl. }$.
    
    For two integer numbers $x$ and $y$, the \emphi{quotient} of $x/y$
    is $x \bdiv y = \floor{x/y}$. The \emphi{remainder} of $x/y$ is
    $x \bmod y = x - y \floor{x/y}$. If the $x \bmod y = 0$, than $y$
    \emphi{divides} $x$, denoted by $y \divides x$.  We use
    $\alpha \equiv \beta \pmod{p}$ or $\alpha \equiv_p \beta$ to
    denote that $\alpha$ and $\beta$ are \emphi{congruent modulo $p$};
    that is $\alpha \bmod p = \beta \bmod p$ -- equivalently,
    $p \divides \pth[]{\alpha - \beta}$.
\end{defn}

\begin{remark}
    A quick review of what we already know. 
    Let $p$ be a prime number.
    %

    \begin{compactenumA}
        \item \lemref{n:t:silly:1}: For any
        $\alpha, \beta \in \brc{ 1, \ldots, p-1}$, we have that
        $\alpha \beta \not \equiv 0 \pmod{p}$.

        \item \lemref{n:t:silly:1}: For any
        $\alpha, \beta, i \in \brc{ 1,\ldots, p-1}$, such that
        $\alpha \ne \beta$, we have that
        $\alpha i \nequiv \beta i \pmod{p}$.

        
        \item \lemref{n:t:silly:1}: For any
        $x \in \brc{1,\ldots, p-1}$ there exists a unique $y$ such
        that $xy \equiv 1 \pmod{p}$. The number $y$ is the
        \emphi{inverse} of $x$, and is denoted by $x^{-1}$ or $1/x$. %

        \item \lemref{r:s:not:equal}: For any numbers
        $x, y \in \ZZ_p$.  If $x \neq y$ then, for any
        $a, b \in \mathbb{Z}_p$, such that $a \neq 0$, we have
        $a x + b \nequiv a y + b \pmod p$.

        \item \lemref{unique:inverse}: For any numbers
        $x, y \in \ZZ_p$.  If $x \neq y$ then, for each pair of
        numbers $r,s \in \ZZ_{p} = \{0,1, \ldots, p-1\}$, such that
        $r \neq s$, there is exactly one unique choice of numbers
        $a,b \in \ZZ_p$ such that $ax + b \pmod p = r$ and
        $ay + b \pmod p = s$.

    \end{compactenumA}
\end{remark}




\subsubsection{Constructing a family of $2$-universal hash functions}

For parameters $N = |\cU|$, $m = |T|$, $n = |S|$. Choose a
\emphi{prime} number $p \ge N$. Let
\begin{equation*}
    \cH = \Set{h_{a,b} }{a,b \in \ZZ_p \text{ and } a \neq 0},
\end{equation*}
where $h_{a,b}(x) = ((ax + b) \pmod p) \pmod m$. Note that
$|\cH| = p(p-1)$. %

\subsubsection{Analysis}

Once we fix $a$ and $b$, and we are given a value $x$, we compute the
hash value of $x$ in two stages:
\begin{compactenumA}
    \item \emphi{Compute}: $r \leftarrow (a x + b) \pmod p$.
    
    \item \emphi{Fold}: $r' \leftarrow r \pmod m$%.
\end{compactenumA}

\begin{lemma}
    \lemlab{folding}%
    %
    Assume that $p$ is a prime, and $1 < m < p$.  The number of pairs
    $(r,s) \in \ZZ_p \times \ZZ_p$, such that $r \neq s$, that are
    folded to the same number is $\leq p(p-1)/m$.  Formally, the set
    of bad pairs
    \begin{equation*}
        B = \Set{(r,s) \in \ZZ_p \times \ZZ_p}{ r \equiv_m s  }
    \end{equation*}
    is of size at most $p(p-1)/m$.
\end{lemma}
\begin{proof}
    Consider a pair $(x,y) \in \brc{0, 1,\ldots, p-1}^2$, such that
    $x \neq y$. For a fixed $x$, there are at most $\ceil{p/m}$ values
    of $y$ that fold into $x$. Indeed, $x \equiv_m y$ if and only if
    \begin{equation*}
        y \in L(x) = \Set{x + im }{i \text { is an integer}} \cap \ZZ_p.
    \end{equation*}
    The size of $L(x)$ is maximized when $x = 0$, The number of such
    elements is at most $\ceil{p/m}$ (note, that since $p$ is a prime,
    $p/m$ is fractional).  One of the numbers in $O(x)$ is $x$ itself.
    As such, we have that
    \begin{equation*}
        \cardin{B}%
        \leq%
        p \bigl(\cardin{L(x)}  - 1 \bigr)%
        \leq%
        p \bigl(\ceil{p/m} - 1 \bigr)
        \leq%
        p \bigl(p - 1 \bigr)/m,
    \end{equation*}
    since
    $\ceil{p/m} - 1 \leq (p-1)/m$
    $\iff$
    $m\ceil{p/m} - m \leq p-1$
    $\iff$
    $m\floor{p/m} \leq p-1$
    $\iff$
    $m\floor{p/m} < p$,
    which is true since $p$ is a prime, and $1 <m < p$.    
\end{proof}


\begin{claim}
    \clmlab{bad:pairs}%
    %
    For two distinct numbers $x, y \in \cU$, a pair $a,b$ is
    \emphi{bad} if $h_{a,b}(x) = h_{a,b}(y)$.  The number of bad pairs
    is $\leq p(p-1)/m$.
\end{claim}

\begin{proof}
    Let $a,b \in \mathbb{Z}_p$ such that $a \neq 0$ and
    $h_{a,b}(x) = h_{a,b}(y)$. Let 
    \begin{equation*}
        r = (ax+ b) \bmod p
        \qquad\text{and}\qquad%
        s = (a y + b)  \bmod p.
    \end{equation*}
    By \lemref{r:s:not:equal}, we have that $r \neq s$. As such, a
    collision happens if $r \equiv s \pmod{m}$.  By \lemref{folding},
    the number of such pairs $(r,s)$ is at most $p(p-1)/m$.  By
    \lemref{unique:inverse}, for each such pair $(r,s)$, there is a
    unique choice of $a,b$ that maps $x$ and $y$ to $r$ and $s$,
    respectively. As such, there are at most $p(p-1)/m$ bad pairs.
\end{proof}%


\begin{theorem}
    \thmlab{2:universal:h:f}%
    %
    The hash family $\cH$ is a $2$-universal hash family.
\end{theorem}

\begin{proof}
    Fix two distinct numbers $x, y \in \cU$. We are interested in the
    probability they collide if $h$ is picked randomly from $\cH$.  By
    \clmref{bad:pairs} there are $M \leq p(p-1)/m$ bad pairs that
    causes such a collision, and since $\cH$ contains $N = p(p-1)$
    functions, it follows the probability for collision is
    $M /N \leq 1/m$, which implies that $\cH$ is $2$-universal.
\end{proof}

\subsubsection{Explanation via pictures}

Consider a pair $(x,y)\in \ZZ_p^2$, such that $x \neq y$. This pair
$(x,y)$ corresponds to a cell in the natural ``grid'' $\ZZ_p^2$ that
is off the main diagonal.  See \figref{grid:p:m}


The mapping $f_{a,b}(x) = (ax + b) \bmod p$, takes the pair $(x,y)$,
and maps it randomly and uniformly, to some other pair
$x' = f_{a,b}(x)$ and $y' = f_{a,b}(y)$ (where $x', y'$ are again off
the main diagonal).

Now consider the smaller grid $\ZZ_m \times \ZZ_m$. The main diagonal
of this \si{subgrid} is bad -- it corresponds to a collision. One can
think about the last step, of computing
$h_{a,b}(x) = f_{a,b}(x) \bmod m$, as tiling the larger grid, by the
smaller grid. in the natural way. Any diagonal that is in distance
$mi$ from the main diagonal get marked as bad. At most $1/m$ fraction
of the off diagonal cells get marked as bad.
See    \figref{grid:p:m}.

As such, the random mapping of $(x,y)$ to $(x',y')$ causes a collision
only if we map the pair to a badly marked pair, and the probability
for that $\leq 1/m$.

\section{Perfect hashing}%


An interesting special case of hashing is the static case -- given a
set $S$ of elements, we want to hash $S$ so that we can answer
membership queries efficiently (i.e., dictionary data-structures with
no insertions). it is easy to come up with a hashing scheme that is
optimal as far as space.

\subsection{Some easy calculations}

The first observation is that if the hash table is quadraticly large,
then there is a good (constant) probability to have no collisions
(this is also the threshold for the birthday paradox).

\begin{lemma}
    \lemlab{h:t:quadratic}%
    %
    Let $S \subseteq \cU$ be a set of $n$ elements, and let $\cH$ be a
    $2$-universal family of hash functions, into a table of size
    $m \geq n^2$. Then with probability $\leq 1/2$, there is a pair
    of elements of $S$ that collide under a random hash function $h
    \in \cH$.
\end{lemma}
\begin{proof}
    For a pair $x, y \in S$, the probability they collide is at most
    $\leq 1/m$, by \defrefY{definition}{2:universal}. As such, by the
    union bound, the probability of any collusion is
    $\binom{n}{2}/m = n(n-1)/2m \leq 1/2$.
\end{proof}

We now need a second moment bound on the sizes of the buckets.

\begin{lemma}
    \lemlab{second:moment:h:t}%
    %
    Let $S \subseteq \cU$ be a set of $n$ elements, and let $\cH$ be a
    $2$-universal family of hash functions, into a table of size
    $m \geq cn$, where $c$ is an arbitrary constant. Let $h \in \cH$
    be a random hash function, and let $X_i$ be the number of elements
    of $S$ mapped to the $i$\th bucket by $h$, for $i=0,\ldots, m-1$.
    Then, we have
    \begin{math}
        \ExChar \Bigl[\sum_{j=0}^{m-1} X_j^2 \Bigr] \leq (1+1/c)n.
    \end{math}
\end{lemma}
\begin{proof}
    Let $s_1, \ldots, s_n$ be the $n$ items in $S$, and let
    $Z_{i,j} =1$ if $h(s_i) = h(s_j)$, for $i < j$.  Observe that
    $\Ex{Z_{i,j} } = \Prob{h(s_i) = h(s_j)} \leq 1/m$ (this is the
    only place we use the property that $\cH$ is $2$-universal).  In
    particular, let $\mathcal{Z}(\alpha)$ be all the variables
    $Z_{i,j}$, for $i<j$, such that $Z_{i,j}=1$ and
    $h(s_i) = h(s_j) = \alpha$.
    
    If for some $\alpha$ we have that $X_\alpha = k$, then there are
    $k$ indices $\ell_1 < \ell_2 < \ldots < \ell_k$, such that
    $h(s_{\ell_1}) = \cdots = h(s_{\ell_k}) = i$. As such,
    $z(\alpha)=\cardin{\mathcal{Z}(\alpha)} = \binom{k}{2}$. In
    particular, we have
    \begin{equation*}
        X_\alpha^2%
        =%
        k^2 %
        =%
        2 \binom{k}{2}  + k%
        =%
        2 z(\alpha) + X_\alpha
    \end{equation*}
    This implies that
    \begin{equation*}
        \sum_{\alpha=0}^{m-1} X_\alpha^2%
        =%
        \sum_{\alpha=0}^{m-1} \pth{\bigl.2 z(\alpha) + X_\alpha}
        =%
        2 \sum_{\alpha=0}^{m-1}  z(\alpha) + \sum_{\alpha=0}^{m-1}  X_\alpha
        =%
        % 2 \sum_{i\alpha=0}^{m-1} z(\alpha) + \sum_{\alpha=0}^{m-1}
        % X_\alpha =%
        n +  2 \sum_{i=1}^{n-1} 
        \sum_{j=i+1}^n Z_{ij}%
    \end{equation*}
    Now, by linearity of expectations, we have
    \begin{align*}
      \Ex{\smash{\sum_{\alpha=0}^{m-1} X_\alpha^2}\Bigr.}%
      &=%
        \Ex{n +  \smash{2 \sum_{i=1}^{n-1} 
        \sum_{j=i+1}^n Z_{ij} } \Bigr.}%
        =%
        n +  2 \sum_{i=1}^{n-1} 
        \sum_{j=i+1}^n\Ex{ Z_{ij} } %
        \leq %
        n +  2 \sum_{i=1}^{n-1} \sum_{j=i+1}^n\frac{1}{m} %
      \\&%
      = %
      n +  \frac{2}{m} \binom{n}{2}%
      = %
      n  +  \frac{2n(n-1)}{2m}
      \leq% 
      n \pth{1 +  \frac{n-1}{m}}
      \leq 
      n\pth{1  + \frac{1}{c}}
    \end{align*}
    since $m \geq c n$.
\end{proof}


\subsection{Construction of perfect hashing}

Given a set $S$ of $n$ elements, we build a open hash table $T$ of
size, say, $2n$. We use a random hash function $h$ that is
$2$-universal for this hash table, see \thmref{2:universal:h:f}. Next,
we map the elements of $S$ into the hash table.  Let $S_j$ be the list
of all the elements of $S$ mapped to the $j$\th bucket, and let
$X_j = \cardin{L_j}$, for $j=0,\ldots, n-1$.

We compute $Y = \sum_{i=1} X_j^2$. If $Y > 6n$, then we reject $h$,
and resample a hash function $h$. We repeat this process till success.

In the second stage, we build secondary hash tables for each bucket.
Specifically, for $j=0,\ldots, 2n-1$, if the $j$\th bucket contains
$X_j > 0$ elements, then we construct a secondary hash table $H_j$ to
store the elements of $S_j$, and this secondary hash table has size
$X_j^2$, and again we use a random $2$-universal hash function $h_j$
for the hashing of $S_j$ into $H_j$. If any pair of elements of $S_j$
collide under $h_j$, then we resample the hash function $h_j$, and try
again till success.

\subsubsection{Analysis}

\begin{theorem}
    Given a (static) set $S \subseteq \cU$ of $n$ elements, the above
    scheme, constructs, in expected linear time, a two level
    hash-table that can perform search queries in $O(1)$ time. The
    resulting data-structure uses $O(n)$ space.
\end{theorem}
\begin{proof}   
    Given an element $x \in \cU$, we first compute $j = h(x)$, and
    then $k = h_j(x)$, and we can check whether the element stored in
    the secondary hash table $H_j$ at the entry $k$ is indeed $x$. As
    such, the search time is $O(1)$.

    The more interesting issue is the construction time.  Let $X_j$ be
    the number of elements mapped to the $j$\th bucket, and let
    $Y = \sum_{i=1}^n X_i^2$.  Observe, that
    $\Ex{Y} \leq (1+ 1/2)n =(3/ 2)n$, by \lemref{second:moment:h:t}
    (here, $m=2n$ and as such $c=2$). As such, by Markov's inequality,
    $\Prob{X > 6n} = \frac{(3/2)n}{6n} \leq 1/4$. In particular,
    picking a good top level hash function requires in expectation at
    most $1/(3/4)=4/3 \leq 2$ iterations. Thus the first stage takes
    $O(n)$ time, in expectation.

    For the $j$\th bucket, with $X_j$ entries, by
    \lemref{h:t:quadratic}, the construction succeeds with probability
    $\geq 1/2$. As before, the expected number of iterations till
    success is at most $2$. As such, the expected construction time of
    the secondary hash table for the $j$\th bucket is $O(X_j^2)$.

    We conclude that the overall expected construction time is
    $O( n + \sum_j X_j^2 ) = O(n)$.

    As for the space used, observe that it is $O(n + \sum_j X_j^2 ) =
    O(n)$.    
\end{proof}

\section{Bloom filters}

Consider an application where we have a set $S \subseteq \cU$ of $n$
elements, and we want to be able to decide for a query $x \in \cU$,
whether or not $x \in S$. Naturally, we can use hashing. However, here
we are interested in more efficient data-structure as far as space. We
allow the data-structure to make a mistake (i.e., say that an element
is in, when it is not in).

\paragraph*{First try.}
So, let start silly. Let $B[0\ldots, m]$ be an array of bits, and pick
a random hash function $h:\cU \rightarrow \ZZ_m$. Initialize $B$ to
$0$. Next, for every element $s \in S$, set $B[h(s)]$ to $1$. Now,
given a query, return $B[h(x)]$ as an answer whether or not $x \in
S$. Note, that $B$ is an array of bits, and as such it can be
bit-packed and stored efficiently.

For the sake of simplicity of exposition, assume that the hash
functions picked is truly random. As such, we have that the
probability for a false positive (i.e., a mistake) for a fixed
$x \in \cU$ is $n/m$. Since we want the size of the table $m$ to be
close to $n$, this is not satisfying.


\paragraph*{Using $k$ hash functions.}
Instead of using a single hash function, let us use $k$ independent
hash functions $h_1, \ldots h_k$. For an element $s \in S$, we set
$B[h_i(s)]$ to $1$, for $i=1,\ldots, k$.  Given an query $x \in \cU$,
if $B[h_i(x)]$ is zero, for any $i=1,\ldots, k$, then $x \notin
S$. Otherwise, if all these $k$ bits are on, the data-structure
returns that $x$ is in $S$.


Clearly, if the data-structure returns that $x$ is not in $S$, then it
is correct. The data-structure might make a mistake (i.e., a false
positive), if it returns that $x$ is in $S$ (when is not in $S$).

We interpret the storing of the elements of $S$ in $B$, as an
experiment of throwing $kn$ balls into $m$ bins. The probability of a
bin to be empty is
\begin{equation*}
    p = p(m,n) = (1-1/m)^{kn} \approx \exp \pth{-k(n/m)}.
\end{equation*}
Since the number of empty bins is a martingale, we know the number of
empty bins is strongly concentrated around the expectation $p m$, and
we can treat $p$ as the true probability of a bin to be empty.

The probability of a mistake is
\begin{equation*}
    f(k,m,n) = (1-p)^k.
\end{equation*}
In particular, for $k = (m/n)\ln n$, we have that
$p = p(m,n) \approx 1/2$, and
$f(k,m,n) \approx 1/2^{(m/n)\ln 2} \approx 0.618^{m/n}$.

\begin{example}
    Of course, the above is fictional, as $k$ has to be an
    integer. But motivated by these calculations, let $m=3n$, and
    $k=4$.  We get that $p(m,n) = \exp( -4/3) \approx 0.26359$, and
    $f( 4,3n,n) \approx (1-0.265)^4 \approx 0.294078$. This is
    better than the naive $k=1$ scheme, where the probability of false
    positive is $1/3$.    
\end{example}

Note, that this scheme gets exponentially better over the naive scheme
as $m/n$ grows.

\begin{example}
    Consider the setting $m=8n$ -- this is when we allocate a byte for
    each element stored (the element of course might be significantly
    bigger). The above implies we should take
    $k =\ceil{ (m/n)\ln 2} = 6$. We then get
    $p(8n,n) = \exp( -6/8) \approx 0.5352$, and
    $f(6,8n,n) \approx 0.0215$. Here, the naive scheme with $k=1$,
    would give probability of false positive of $1/8 =0.125$. So this
    is a significant improvement.
\end{example}

\begin{remark}
    It is important to remember that Bloom filters are competing with
    direct hashing of the whole elements. Even if one allocates $8$
    bits per item, as in the example above, the space it uses is
    significantly smaller than regular hashing. A situation when such
    a Bloom filter makes sense is for a cache -- we might want to
    decide if an element is in a slow external cache (say S{S}D
    drive). Retrieving item from the cache is slow, but not so slow we
    are not willing to have a small overhead because of false
    positives.
\end{remark}
