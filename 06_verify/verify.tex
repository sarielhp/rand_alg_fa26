\section{Verifying equality}

\subsection{Vectors}

You are given two binary vectors
$\vecA = (v_1, \ldots, v_n), \vecB = (u_1, \ldots, u_n) \in
\brc{\bigl. 0,1}^n$ and you would like to decide if they are equal or
not. Unfortunately, the only access you have to the two vectors is via
a black-box that enables you to compute the dot-product of two binary
vectors over $\ZZ_2$. Formally, given two binary vectors as above,
their dot-product is $\DotProd{\vecA}{\vecB} = \sum_{i=1}^n v_i u_i$
(which is a non-negative integer number). Their dot product modulo
$2$, is \;$\DotProd{\vecA}{\vecB} \bmod 2$\; (i.e., it is $1$ if
$\DotProd{\vecA}{\vecB}$ is odd and $0$ otherwise).

Naturally, we could the use the black-box to read the vectors (using
$2n$ calls), but since we are interested only in deciding if they are
equal or not, this should require less calls to the black-box (which
is expensive).

\begin{lemma}
    \lemlab{verify:vectors:1:2}%
    %
    Given two binary vectors $\vecA, \vecB \in \brc{\bigl. 0,1}^n$, a
    randomized algorithm can, using two computations of dot-product
    modulo 2, decide if $\vecA$ is equal to $\vecB$ or not.  The
    algorithm may return one of the following two values:
    \begin{compactenumA}
        \item[$\boldsymbol \ne$:] Then $\vecA \neq \vecB$.

        \item[$\boldsymbol =$:] Then the probability that the
        algorithm made a mistake (i.e., the vectors are different) is
        at most $1/2$.
    \end{compactenumA}
    The running time of the algorithm is $O( n + B(n))$, where $B(n)$
    is the time to compute a single dot-product of vectors of length
    $n$.
\end{lemma}
\begin{proof}
    Pick a random vector
    $\vecRand = \pth[]{r_1, \ldots, r_n} \in \brc{ 0,1}^n$ by picking
    each coordinate independently with probability $1/2$. Compute the
    two dot-products $\DotProd{\vecA}{\vecRand}$ and
    $\DotProd{\vecB}{\vecRand}$.
    \begin{compactenumA}
        \item If $\DotProd{\vecA}{\vecRand} \equiv
        \DotProd{\vecA}{\vecRand} \bmod 2$ $\quad\Rightarrow\quad$ the
        algorithm returns `$\boldsymbol =$'.
        \item If $\DotProd{\vecA}{\vecRand} \nequiv
        \DotProd{\vecA}{\vecRand} \bmod 2$ $\quad\Rightarrow\quad$ the
        algorithm returns `$\boldsymbol \ne$'.
    \end{compactenumA}
    Clearly, if the `$\boldsymbol \ne$' is returned then
    $\vecA \neq \vecB$.

    So, assume that the algorithm returned `$\boldsymbol =$' but
    $\vecA \neq \vecB$. For the sake of simplicity of exposition,
    assume that they differ on the $n$\th bit: $u_n \neq v_n$. We then
    have that
    \begin{align*}
        \alpha = \DotProd{\vecA}{\vecRand} =
        \overbrace{\sum_{i=1}^{n-1} v_i r_i}^{=\alpha'} \quad+\quad
        v_n r_n%
        \text{\qquad and\qquad }%
        \beta = \DotProd{\vecB}{\vecRand} =
        \overbrace{\sum_{i=1}^{n-1} u_i r_i}^{=\beta'} \quad+\quad u_n
        r_n.
    \end{align*}
    Now, there are two possibilities:
    \begin{compactenumA}
        \smallskip%
        \item If $\alpha' \nequiv \beta' \bmod 2$, then, with
        probability half, we have $r_i = 0$, and as such $\alpha
        \nequiv \beta \bmod 2$.
        \smallskip%
        \item If $\alpha' \equiv \beta' \bmod 2$, then, with
        probability half, we have $r_i = 1$, and as such $\alpha
        \nequiv \beta \bmod 2$.
    \end{compactenumA}
    \smallskip%
    As such, with probability at most half, the algorithm would fail
    to discover that the two vectors are different.
\end{proof}

\newcommand{\RetEq}{\ensuremath{\text{`$\boldsymbol =$'}}\xspace}
\newcommand{\RetNEq}{\ensuremath{\text{`$\boldsymbol =$'}}\xspace}

\subsubsection{Amplification}

Of course, this is not a satisfying algorithm -- it returns the
correct answer only with probability half if the vectors are
different. So, let us run the algorithm $t$ times.  Let $T_1, \ldots,
T_t$ be the returned values from all these executions.  If any of the
$t$ executions returns that the vectors are different, then we know
that they are different.
\begin{align*}
  \Prob{ \bigl. \text{Algorithm fails}}%
  &=%
    \Prob{ \bigl. \vecA \neq \vecB, \text{ but all $t$ executions
    return `$\boldsymbol =$'}}%
  \\
  &=%
    \Bigl.\Prob{ \bigl.%
    \pth[]{\bigl. T_1 = \RetEq}%
    \cap%
    \pth[]{\bigl. T_2 = \RetEq}%
    \cap%
    \cdots%
    \cap%
    \pth[]{\bigl. T_t = \RetEq}%
    }%
  \\%
  &=%
    \Prob{ \bigl.%
    {\bigl. T_1 = \RetEq}%
    }%
    \Prob{ {\bigl. T_2 = \RetEq} }%
    \cdots%
    \Prob{ {\bigl. T_t = \RetEq} }%
    \leq \prod_{i=1}^t \frac{1}{2} = \frac{1}{2^t}.
\end{align*}

We thus get the following result.

\begin{lemma}
    Given two binary vectors $\vecA, \vecB \in \brc{\bigl. 0,1}^n$ and
    a \emphi{confidence} parameter $\delta > 0$, a randomized
    algorithm can decide if $\vecA$ is equal to $\vecB$ or not. More
    precisely, the algorithm may return one of the two following
    results:
    \begin{compactenumA}
        \item[\qquad$\boldsymbol \ne$:] Then $\vecA \neq \vecB$.

        \item[\qquad $\boldsymbol =$:] Then, with probability
        $\geq 1-\delta$, we have $\vecA \neq \vecB$.
    \end{compactenumA}
    The running time of the algorithm is
    $ O\pth{ \bigl. \ts (n + B(n)) \ln \delta^{-1} }$, where $B(n)$ is
    the time to compute a single dot-product of two vectors of length
    $n$.
\end{lemma}

\begin{proof}
    Follows from the above by setting $t= \ceil{\lg (1/\delta)}$.
\end{proof}

\subsection{Matrices}

Given three binary matrices $\MatrixB$, $\MatrixC$, $\MatrixD$ of size
$n \times n$, we are interested in deciding if
$\MatrixB \MatrixC = \MatrixD$. Computing $\MatrixB \MatrixC$ is
expensive -- the fastest known (theoretical!) algorithm has running
time (roughly) $O\pth{n^{2.37}}$. On the other hand, multiplying such
a matrix with a vector $\vecRand$ (modulo $2$, as usual) takes only
$O(n^{2})$ time (and this algorithm is simple).
 

\begin{lemma}
    Given three binary matrices
    $\MatrixB, \MatrixC, \MatrixD \in \brc{\bigl. 0,1}^{n\times n}$
    and a confidence parameter $\delta > 0$, a randomized algorithm
    can decide if $\MatrixB \MatrixC = \MatrixD$ or not. More
    precisely the algorithm can return one of the following two
    results:
    \begin{compactenumA}
        \item[\qquad$\boldsymbol \ne$:] Then $\MatrixB \MatrixC
        \neq \MatrixD$.

        \item[\qquad $\boldsymbol =$:] Then
        $\MatrixB \MatrixC = \MatrixD$ with probability
        $\geq 1 -\delta$.
    \end{compactenumA}
    The running time of the algorithm is
    $ O\pth{ \bigl.  n^2 \log \delta^{-1} }$.
\end{lemma}

\begin{proof}
    Compute a random vector $\vecRand = ( r_1, \ldots, r_n)$, and
    compute the quantity
    $\vecX = \MatrixB \MatrixC \vecRand = \MatrixB \pth[]{ \MatrixC
       \vecRand }$ in $O(n^2)$ time, using the associative property of
    matrix multiplication. Similarly, compute
    $\vecY = \MatrixD \vecRand$. Now, if $\vecX \neq \vecY$ then
    return \RetNEq.

    Now, we execute this algorithm $t = \ceil{\lg \delta^{-1}}$
    times. If all of these independent runs return that the matrices
    are equal then return \RetEq.

    The algorithm fails only if $\MatrixB \MatrixC \neq \MatrixD$, but
    then, assume the $i$\th row in two matrices $\MatrixB \MatrixC$
    and $\MatrixD$ are different. The probability that the algorithm
    would not detect that these rows are different is at most $1/2$,
    by \lemref{verify:vectors:1:2}. As such, the probability that all
    $t$ runs failed is at most $1/2^t \leq \delta$, as desired.
\end{proof}

\subsection{Checking identity for polynomials}

\subsubsection{The Schwartz–Zippel lemma}

Let $\Field$ be a field (i.e., real numbers). Let
$\Field[x_1, \ldots, X_n]$ denote the set of polynomials over the $n$
variables $x_1, \ldots, x_n$ over $\Field$. Such a polynomial is a sum
of monomial, where a \emphi{monomial} has the form
$c \cdot x_1^{i_1} \cdot x_2^{i_2} \cdots x_n^{i_n}$, where
$c \in \Field$. The \emphi{degree} of this monomial is
$\degreeX{c \cdot x_1^{i_1} \cdot x_2^{i_2} \cdots x_n^{i_n}} = i_1 +
i_2 +\cdots + i_n$. Thus, a polynomial of degree $d$ over $n$
variables has potentially up to $d n^d$ monomials (the exact bound is
messier, but an easy lower bound on this quantity is $\binom{n}{d}$).

For a polynomial $f \in \Field[x_1, \ldots, X_n]$, the \emphi{zero
   set} of $f$, is the set
$Z_f = \Set{ (x_1, \ldots, x_n) }{f(x_1, \ldots, x_n) =
   0}$. Intuitively, the zero set $Z_f = \Field^n$ only if
$f(x_1,\ldots, x_n ) =0$ (and then it is the \emphi{zero} polynomial),
but otherwise (i.e., $f \neq 0$) $Z_f$ should be much ``smaller''.


Specifically, a polynomial in a single variable of degree $d$ is
either zero everywhere, or has at most $d$ roots (i.e.,
$|Z_f| \leq d$). This is known as the \emph{fundamental theorem of
   algebra}\footnote{Wikipedia notes that the proof is not algebraic,
   and it is definitely not fundamental to modern algebra. So maybe it
   should be cited as ``the theorem formerly known as the fundamental
   theorem of algebra''.}. The picture gets much messier once one
deals with multi-variate polynomials, but fortunately there is a
simple and elegant lemma that bounds the number of zeros if we pick
the values from the right set of values.



\begin{lemma}[Schwartz–Zippel]
    \lemlab{Schwartz:Zippel}
    %
    Let
    \begin{math}
        f \in \Field[x_1, \ldots, x_n]
    \end{math}
    be a non-zero polynomial of total degree $d \geq 0$, over a field
    $\Field$.  Let $S \subseteq \Field$ be finite. Let
    $\mathsf{r} = (r_1, \ldots, r_n)$ be randomly and uniformly chosen
    from $S^n$. Then
    \begin{equation*}
        \Prob{ f( \mathsf{r} ) = 0 } \leq \frac{d}{|S|}.
    \end{equation*}
    Equivalently, we have $|Z_f \cap S^n| \leq d |S|^{n-1}$.
\end{lemma}
\begin{proof}
    The proof is by induction on $n$. For $n = 1$, by the theorem,
    formally known as the fundamental theorem of algebra,
    $|Z_f \cap S| \leq |Z_f| \leq d$. So assume the theorem holds for
    $n-1$. Since $f$ is non-zero, it can be written as a sum of $d$
    polynomials in $n-1$ variables. That is, $f$ can be written as
    \begin{equation*}
        f(x_1, \ldots, x_n)
        =%
        \sum_{i=0}^d x_1^i f_i(x_2, \ldots, x_n),
    \end{equation*}
    where $\degreeX{f_i} \leq d-i$.  Since $f$ is not zero, one of the
    $f$s must be non-zero, and let $i$ the maximum value such that
    $f_i \neq 0$.

    Now, we randomly choose the values $r_2, \ldots, r_n \in S$
    (independently and uniformly). And consider the polynomial in the
    single variable $x$, which is
    \begin{equation*}
        g(x) = \sum_{j=0}^d f_j(r_2, \ldots,r_n) x^i.
    \end{equation*}
    Let $\EventF$ be the event that $f_i(r_2, \ldots, r_n) = 0$.  Let
    $\EventG$ be the event that $g(x) = 0$.  By induction, we have
    $\Prob{\EventF} \leq (d-i)/|S|$. More interestingly if $\EventF$
    does not happen, then $\degreeX{g} = i$. As such, by induction, we
    have that
    \begin{equation*}
        \ProbCond{ \EventG}{\smash{\overline{\EventF}}} = \ProbCond{ g(x)
           = 0}{\smash{\overline{\EventF}}}%
        \leq%
        \frac{i}{|S|}.
    \end{equation*}
    We conclude that
    \begin{equation*}
        \Prob{f(\mathsf{r}) = 0}
        =%
        \Prob{\EventG \cap \EventF}
        + 
        \Prob{\EventG \cap \smash{ \overline{\EventF}}}
        \leq%
        \Prob{\EventF} +
        \ProbCond{\EventG}{\smash{\overline{\EventF}} }
        \leq
        \frac{d-i}{|S|} + \frac{i}{|S|}%
        \leq%
        \frac{d}{|S|}.
  \end{equation*}
\end{proof}

\begin{remark}
    Consider the polynomial $f(x,y) = (x-1)^2 + (y-1)^2 - 1$. The zero
    set of this polynomial is the unit circle. So the zero set $Z_f$
    is infinite in this case. However, note that for any choice of
    $S$, the set $S^2$ is a grid. The Schwartz-Zippel lemma, tells us
    that there relatively few grid points that are in the zero set.
\end{remark}

\subsubsection{Applications}

\paragraph{Checking if a polynomial is the zero polynomial.}

Let $f$ be a polynomial of degree $d$, with $n$ variables, over the
reals that can be evaluated in $O(T)$ time. One can check if $f$ zero,
by picking randomly a $n$ numbers from $S= \IRX{d^3}$. By
\lemref{Schwartz:Zippel}, we have that the probability of $f$ to be
zero over the chosen values is $\leq d/d^3$, which is a small
number. As above, we can do amplification to get a high confidence
answer.

\paragraph{Checking if two polynomials are equal.}

Given two polynomials $f$ and $g$, one can now check if they are equal
by checking if $f(r)=g(r)$, for some random input. The proof of
correctness follows from the above, as one interpret the algorithm as
checking if $f-g$ is the zero polynomial.

\paragraph{Verifying  polynomials product.}

Given three polynomials $f,g$, and $h$, one can now check if
$f g = h$. Again, one randomly pick a value $r$, and check if
$f(r)g(r)=h(r)$. The proof of correctness follows from the above, as
one interprets the algorithm as checking if $fg - h$ is the zero
polynomial.


\subsection{Checking if a bipartite graph has a perfect matching}

Let $\G =(L\cup R,\Edges)$ be a bipartite graph. Let $L = \{ u_1, \ldots,
u_n\}$ and $R= \{v_1,\ldots, v_n\}$. Consider the set of variables
\begin{equation*}
    \mathcal{V} =\Set{x_{i,j}}{u_i v_j \in \Edges}.
\end{equation*}
Let $M$ be an $n \times n$ matrix, where $M[i,j]=0$ if
$u_iv_j \notin \Edges$, and $M[i,j] = x_{i,j}$ otherwise.  Let $\Pi$
be the set of all permutations of $\IRX{n}$.

A \emphi{perfect matching} is a permutation
$\pi:\IRX{n}\rightarrow \IRX{n}$, such that for all $i$, we have
$u_i v_{\pi(i)} \in \Edges$. For such a permutation $\pi$, consider
the monomial
\begin{equation*}
    f_\pi = \mathrm{sign}(\pi) \prod_{i=1}^n M[i,j],
\end{equation*}
where $\mathrm{sign}$ is the \emphi{sign} of the permutation (it is
either $-1$ or $+1$ -- for our purpose here we do not care about the
exact definition of this quantity).  It is either a polynomial of
degree exactly $n$, or it is zero. Furthermore, observe that for any
two different permutation $\pi,\sigma \in \Pi$, we have that if
$f_\pi$ and $f_\sigma$ are both non-zero, then $f_\pi \neq f_\sigma$
and $f_\pi \neq -f_\sigma$.

Consider the following ``crazy'' polynomial over the set of variables
$\mathcal{V}$:
\begin{equation*}
    \psi  =
    \psi( \mathcal{V})%
    =%
    \det(M)
    =%
    \sum_{\pi \in \Pi}
    \mathrm{sign}(\pi) f_\pi.
\end{equation*}
If there is perfect matching in $\Graph$, then there is a permutation
$\pi$ such that $f_\pi \neq 0$. But this implies that $\psi \neq 0$
(since it has a non-zero monomials, and the monomials can not cancel
each other).

In the other direction, if there is no perfect matching in $\G$, then
$f_\pi = 0$ for all permutation $\pi$. This implies that
$\psi=0$. Thus, deciding if $\G$ has a perfect matching is equivalent
to deciding if $\psi \neq 0$. The polynomial $\psi$ is defined via a
determinant of a matrix that variables as some of the entries (and
zeros otherwise). By the above, all we need to do is to evaluate
$\psi$ over some random values. If we use exact arithmetic, we would
just pick a random number in $[0,1]$ for each variable, and evaluate
$\psi$ for these values of the variable. Namely, we filled the matrix
$M$ with values (so it is all numbers now), and we need to computes
its determinant. Via Gaussian elimination, the determinant can be
computed in cubic time. Thus, we can evaluate $\psi$ in cubic time,
which implies that with high probability we can check if $\G$ has a
perfect matching.

If we do not want to be prisoners of the impreciseness of floating
point arithmetic, then one can perform the above calculations over
some finite field (usually, the field is simply working modulo a prime
number).

\section{Las Vegas and Monte Carlo algorithms}
\seclab{complexity}

\begin{defn}
    A \emphic{Las Vegas algorithm}{algorithm!Las Vegas} is a
    randomized algorithms that {\em always} return the correct result.
    The only variant is that it's running time might change between
    executions.
\end{defn}

An example for a Las Vegas algorithm is the \Algorithm{QuickSort}
algorithm.

\begin{defn}
    A \emphic{Monte Carlo algorithm}{algorithm!Monte Carlo}
    is a randomized algorithm that might output an incorrect result.
    However, the probability of error can be diminished by repeated
    executions of the algorithm.
\end{defn}

The matrix multiplication algorithm is an example of a Monte Carlo
algorithm.

\subsection{Complexity Classes}

I assume people know what are Turing machines, \CClass{NP},
\CClass{NPC}, RAM machines, uniform model, logarithmic model.
\CClass{PSPACE}, and \CClass{EXP}. If you do now know what are those
things, you should read about them. Some of that is covered in the
randomized algorithms book, and some other stuff is covered in any
basic text on complexity theory\footnote{There is also the internet.}.


\begin{defn}\index{Complexity!\CClass{P}}
    The class \CClass{P} consists of all languages $L$ that have a
    polynomial time algorithm $\Algorithm{Alg}$, such that for any
    input $\Sigma^{*}$, we have
    \begin{compactenumA}
        \item $x \in L \Rightarrow \Algorithm{Alg}(x)$ accepts,
        \item $x \notin L \Rightarrow \Algorithm{Alg}(x)$ rejects.
    \end{compactenumA}
\end{defn}

\begin{defn}\index{Complexity!\CClass{NP}}
    The class \CClass{NP} consists of all languages $L$ that have a
    polynomial time algorithm \Alg, such that for any input
    $\Sigma^{*}$,  we have:
    \begin{compactenumi}
        \item If $x \in L \Rightarrow$ then $\exists y \in \Sigma^*$,
        $\Alg(x,y)$ accepts, where $|y|$ (i.e. the length of $y$) is
        bounded by a polynomial in $|x|$.
     
        \item If $x \notin L \Rightarrow$ then $ \forall y \in
        \Sigma^* \Alg(x,y)$ rejects.
    \end{compactenumi}
\end{defn}

\begin{defn}\index{Complexity!$co-$}
    For a complexity class $\CX$, we define the complementary
    class co-$\CX$ as the set of languages whose complement
    is in the class $\CX$. That is 
    \begin{equation*}
        \coCClass{\CX} = \Set{L}{\bigl.\smash{\overline{L}} \in \CX},
    \end{equation*}4
    where $\overline{L} = \Sigma^* \setminus L$.
\end{defn}

It is obvious that $\CClass{P} = \coCClass{P}$ and $\CClass{P}
\subseteq \CClass{NP} \cap \coCClass{NP}$. (It is currently unknown if
$\CClass{P} = \CClass{NP} \cap \coCClass{NP}$ or whether
$\CClass{NP}=\coCClass{NP}$, although both statements are believed to be
false.)

\begin{defn}\index{Complexity!\CClass{RP}}
    The class \CClass{R{}P} (for Randomized Polynomial time) consists of
    all languages $L$ that have a randomized algorithm \Alg with worst
    case polynomial running time such that for any input $x \in
    \Sigma^*$, we have
    \begin{compactenumi}
        \item If $x \in L$ then $\Prob{\Alg(x) \text{
              accepts}} \geq 1/2$.
     
        \item $x \notin L$ then $\Prob{\Alg(x) \text{
              accepts}} = 0 $.
    \end{compactenumi}
\end{defn}

An \CClass{RP} algorithm is a Monte Carlo algorithm, but this
algorithm can make a mistake only if $x \in L$. As such, \coCClass{RP}
is all the languages that have a Monte Carlo algorithm that make a
mistake only if $x \notin L$. A problem which is in $\CClass{RP} \cap
\coCClass{RP}$ has an algorithm that does not make a mistake, namely a
Las Vegas algorithm.

\begin{defn}\index{Complexity!\CClass{ZPP}}
    The class \CClass{ZPP} (for Zero-error Probabilistic Polynomial
    time) is the class of languages that have a Las Vegas algorithm
    that runs in expected polynomial time.
\end{defn}


\begin{defn}\index{Complexity!\CClass{P{}P}}
    The class \CClassPP (for Probabilistic Polynomial time) is the
    class of languages that have a randomized algorithm \Alg, with
    worst case polynomial running time, such that for any input
    $x \in \Sigma^*$, we have
    \begin{compactenumi}
        \item If $x \in L$ then $\Prob{\MakeBig \Alg(x) \text{
              accepts}} > 1/2$.
     
        \item If $x \notin L$ then $\Prob{\MakeBig\Alg(x) \text{
              accepts}} < 1/2$.
    \end{compactenumi}
\end{defn}

The class \CClassPP is not very useful. Why?

\begin{exercise}
    Provide a \CClassPP algorithm for 3SAT.
\end{exercise}

Consider the mind-boggling stupid randomized algorithm that returns
either yes or no with probability half. This algorithm is almost in
\CClassPP, as it return the correct answer with probability half. An
algorithm is in \CClassPP needs to be \emph{slightly} better, and be
correct with probability better than half. However, how much better
can be made to be arbitrarily close to $1/2$. In particular, there is
no way to do effective amplification with such an algorithm.

\begin{fragment}{\deflabel{b_p_p}}
    \begin{defn}\index{Complexity!\CClass{BPP}}
        \deflab{b:p:p}%
        %
        The class \CClass{BPP} (for Bounded-error Probabilistic Polynomial
        time) is the class of languages that have a randomized algorithm
        \Alg with worst case polynomial running time such that for any
        input $x \in \Sigma^*$, we have
        \begin{compactenumi}
            \item If $x \in L$ then $\Prob{\Alg(x) \text{ accepts}}
            \geq 3/4$.
     
            \item If $x \notin L$ then $\Prob{\Alg(x) \text{ accepts}}
            \leq 1/4$.
        \end{compactenumi}    
    \end{defn}
\end{fragment}
