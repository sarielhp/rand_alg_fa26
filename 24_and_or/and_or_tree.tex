\section{Evaluating an And/Or Tree}
\seclab{complexity}

Let $T_{2k}$ denote a complete binary tree of height $2k$ -- this tree
has $n = 2^{2k}$ leaves. The inputs to the tree are boolean values
stored in the leafs, where nodes are \texttt{AND}/\texttt{OR} nodes
alternatingly. The task at hand is to evaluate the tree - where the
value of a internal node, is the operation associated with the node,
applied to the values returned from evaluating its two children.

\begin{figure}[h]
    \phantom{}\hfill%
    \includegraphics[width=0.3\linewidth]%
    {\File{figs/binary_tree}}%
    \hfill%
    \includegraphics[width=0.3\linewidth]%
    {\File{figs/binary_tree_comp}}%
    \hfill%
    \phantom{}
    \caption{The tree $T_2$, inputs in the leafs, and the output.}
\end{figure}


Defined recursively, $T_2$ is a tree with the root being an
\texttt{AND} gate, and its children are \texttt{OR} gates. This tree
has four inputs. More generally, $T_{2k}$, is $T_2$, with each leaf
replaced by $T_{2k-2}$. Let $n=2^{2k}$.

So the input here is $T_{2k}$, together with $2^{2k}$ values stored in
each leaf of the tree. Consider here the \emph{query model} -- instead
of read the values in the leafs, the algorithm has to explicitly
perform a query to get the value stored in the leaf. The question thus
is can we minimize the number of queries the algorithm needs to
perform.

It is straightforward to evaluate such a tree using a recursive
algorithm in $O(n)$ time. In particular, it following is not too
difficult to show.
\begin{exercise}
    Show that any deterministic algorithm, in the worst case, requires
    $\Omega(n)$ time to evaluate a tree $T_{2k}$.
\end{exercise}

The key observation is that \texttt{AND} (i.e., $\wedge$) gate
evaluation can be shortcut -- that is, if $x=0$ then $x \wedge y = 0$
independently on what value $y$ has. Similarly, an \texttt{OR} (i.e.,
$\vee$) gate evaluation can be shortcut -- since if $x=1$, then
$x\vee y=1$ independently of what $y$ value is.

\subsection{Randomized evaluation algorithm for $T_{2k}$}
The algorithm is recursive. If the current node $v$ is a leaf, the
algorithm returns the value stored at the leaf. Otherwise, the
algorithm randomly chooses (with equal probability) one of the
children of $v$, and evaluate them recursively. If the returned value,
is sufficient to evaluate the gate at $v$, then the algorithm
shortcut. Otherwise, the algorithm evaluates recursively the other
child, computes the value of the gate and return it.

\subsection{Analysis}

\begin{lemma}
    The above algorithm when applied to $T_{2k}$, in expectation,
    reads the value of at most $3^k$ leaves, and this also bounds its
    running time.
\end{lemma}
\begin{proof}
    The proof is by induction. Let start with $T_2$.  There are two
    possibilities:
    \begin{compactenumi}
        \smallskip%
        \item The tree evaluates to $0$, then one of the children of
        the \texttt{AND} gate evaluates zero. But then, with
        probability half the algorithm would guess the right child,
        and evaluate it first. Thus, in this case, the algorithm would
        evaluate (in expectation) $\leq(1/2)2 + (1/2)4 = 3$ leafs.

        \smallskip%
        \item If the output of the tree is $1$, then both children of
        the root must evaluate to $1$. Each one of them is an
        \texttt{OR} gate. Arguing as above, an \texttt{OR} gate
        evaluating to one, requires in expectation to read
        $(1/2)1 + (1/2)2 = 3/2$ leafs to be evaluated by the
        randomized algorithm. It follows, that in this case, the
        algorithm would read (in expectation) $2(3/2) = 3$.  (Note,
        that this is an upper bound -- if all the four inputs are $1$,
        this algorithm would read only $2$ leafs.)
    \end{compactenumi}

    \bigskip%
    
    For $k>1$, consider the four grandchildren of the root
    $c_1, c_2, c_3, c_4$.
    By induction, in expectation, evaluating
    each of $c_1, \ldots, c_4$, takes $3^{k-1}$ leaf evaluations. Let
    $X_1, \ldots, X_4$ be indicator variables that are one if $c_i$ is
    evaluated by the recursive algorithm. Let $Y_i$ be the expected
    number of leafs read when evaluating $c_i$ (i.e.,
    $\Ex{Y_i} = 3^{k}$). By the above, we have that
    $\Ex{\sum_{i} X_i} =3$. Observe that $X_i$ and $Y_i$ are
    independent. (Note, that the $X_i$ are not independent of each
    other.) 
    We thus have that the expected number of leafs to be
    evaluated by the randomized algorithm is 
    \begin{equation*}
        \Ex{\sum_{i} X_iY_i}%
        =%
        \sum_{i}\Ex{ X_iY_i}%
        =%
        \sum_{i}\Ex{ X_i}\Ex{Y_i}%
        \leq%
        3 \Ex{Y_i}%
        =%
        3\cdot 3^{k-1}%
        =%
        3^k.
    \end{equation*}
\end{proof}

\begin{corollary}
    Given an \texttt{AND}/\texttt{OR} tree with $n$ leafs, the above
    algorithm in expectation evaluates
    \begin{equation*}
        3^k = 2^{k \log_2 3} = \pth{2^{2k (\log_2 3)/2}}
        =%
        n^{ (\log_2 3)/2}
        =%
        n^{0.79248}
    \end{equation*}
    leafs.
\end{corollary}

\section{Minimax principle}

Consider a randomized algorithm where the input size is fixed, and the
amount of randomization used by the algorithm is also fixed. One can
consider this to be a game where the algorithm designer chooses the
randomization $r$ (i.e., which randomized algorithm to use), and the
adversary chooses the input $i$. The payoff is then the running time
of the algorithm $T(r,i)$. In particular, one can think about this as
zero sum game with a matrix form, where the designer chooses the row
(i.e., the randomized algorithm), and the adversary chooses the
column. The adversary wants to make the running time as bad as
possible. So if the adversary knows $r$, then it would choose the
input that maximizes $T(r,i)$. Similarly, if the designer knows the
input, then it would choose $r$ that minimizes $T(r,i)$. Thus, the
best the designer can hope to do (i.e., the minimum it would have to
pay) is
\begin{equation*}
    \min_r \max_i T(r,i). 
\end{equation*}
On the other hand, the adversary, can always make the designer pay at
least 
\begin{equation*}
    \max_i \min_r T(r,i).
\end{equation*}

The \emphi{minimax principle} states that
\begin{equation*}
    \min_r \max_i T(r,i) = \max_i \min_r T(r,i).
\end{equation*}
(This follows from either the strong duality theorem of LP, or
fixed-point theorems -- it is not an obvious statement.)

\section{Bibliographical notes}

The \texttt{AND}/\texttt{OR} tree algorithm is from Marc Snir work
\cite{s-lbpld-85}. One can show a lower bound using Yao's min-max
principle, which is implied by the minimax principle of zero sum
games.
